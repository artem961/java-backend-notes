# AOP в Spring: аспекты, прокси, pointcut, advice

**AOP** (аспектно-ориентированное программирование) — способ вынести «сквозную»
логику (логирование, транзакции, безопасность), которая иначе повторялась бы во
множестве методов, в **одно место** и автоматически применять её к нужным методам.
Разберём идею и термины.

## Проблема, которую решает AOP

Представь, что в каждый метод сервиса надо добавить логирование времени выполнения:

```java
public void doWork() {
    long start = System.currentTimeMillis();   // повтор
    // ... собственно логика ...
    log.info("заняло {} мс", System.currentTimeMillis() - start);   // повтор
}
```

Такой код-обвязка пришлось бы копировать в сотни методов. Это **сквозная
функциональность** — она нужна везде, но не относится к бизнес-логике. AOP позволяет
описать её **один раз** и сказать «применяй ко всем методам сервисов».

## Как AOP работает: прокси

Ключевой механизм — **прокси** (заместитель). Вместо твоего бина Spring подсовывает
его **обёртку**. Когда кто-то вызывает метод, он на самом деле попадает в прокси:
тот выполняет дополнительную логику (например, логирование), а потом вызывает
настоящий метод.

```mermaid
flowchart LR
    Caller["Вызывающий код"] --> Proxy["Прокси (обёртка)"]
    Proxy -->|"до: логирование / открыть транзакцию"| Real["Настоящий бин"]
    Real -->|"после: закрыть транзакцию"| Proxy
    Proxy --> Caller
```

Именно так работают `@Transactional` (прокси открывает и закрывает транзакцию
вокруг метода) и Spring Security.

## Термины

- **Aspect (аспект)** — модуль со сквозной логикой (например, «логирование всех
  сервисов»).
- **Advice (совет)** — что именно делать и когда: `@Before` (до метода), `@After`
  (после), `@Around` (обернуть до и после), `@AfterThrowing` (при исключении).
- **Pointcut (срез)** — выражение, которое описывает, **к каким методам** применять
  advice (например, «все методы в пакете `service`»).
- **Join point (точка соединения)** — конкретное место, куда можно вклиниться (вызов
  метода).

```java
@Aspect
@Component
class LoggingAspect {
    @Around("execution(* com.app.service.*.*(..))")   // pointcut: все методы сервисов
    public Object logTime(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = pjp.proceed();                // вызвать настоящий метод
        log.info("заняло {} мс", System.currentTimeMillis() - start);
        return result;
    }
}
```

## Важное следствие: работает только через прокси

Раз AOP работает через прокси-обёртку, есть ограничение: если метод бина вызывает
**другой свой метод напрямую** (`this.method()`), вызов идёт мимо прокси, и advice
**не сработает**. Это та же причина, по которой ломается `@Transactional` при
self-invocation.

## Когда AOP полезен

Хорошие кандидаты — то, что нужно **везде и одинаково**: транзакции, логирование,
замер метрик, проверка прав, кэширование, ретраи. Не стоит через AOP прятать
бизнес-логику — её сложнее читать и отлаживать.

## Что запомнить

- AOP выносит **сквозную** логику (логи, транзакции, безопасность) в одно место.
- Работает через **прокси**: обёртка выполняет доп. логику вокруг настоящего метода.
- Термины: aspect (модуль), advice (что и когда: `@Before`/`@Around`/...), pointcut
  (к каким методам).
- Из-за прокси внутренний вызов `this.method()` идёт мимо AOP — advice не применится.

# Singleton, Factory, Strategy, Builder

**Паттерны проектирования** — типовые проверенные решения частых задач. Знать их
полезно и как «общий язык» с коллегами. Разберём четыре самых ходовых на собеседовании.

## Singleton — один экземпляр на всё приложение

**Задача:** нужен ровно **один** объект этого класса, доступный отовсюду (например, пул
соединений, конфиг).

**Суть:** класс сам контролирует, чтобы его экземпляр был один, и отдаёт всем его.

```java
enum Config {      // enum — самый простой потокобезопасный singleton в Java
    INSTANCE;
    // поля и методы
}
```

Подвох: в многопоточке легко сделать неправильно (два потока создадут два
экземпляра). В Spring об этом думать не надо — бины по умолчанию и так синглтоны
(см. [скоупы](../spring/bean-scopes.md)).

## Factory — создание объектов через отдельный метод

**Задача:** спрятать логику создания объекта, чтобы клиент не делал `new` конкретного
класса и не знал, какой именно класс создаётся.

**Суть:** есть метод-«фабрика», который по входным данным возвращает нужную
реализацию интерфейса.

```java
interface Payment { void pay(); }

class PaymentFactory {
    static Payment create(String type) {
        return switch (type) {
            case "card" -> new CardPayment();
            case "sbp"  -> new SbpPayment();
            default -> throw new IllegalArgumentException(type);
        };
    }
}
```

Клиент просто просит `PaymentFactory.create("card")` и получает `Payment`, не завися
от конкретного класса.

## Strategy — взаимозаменяемые алгоритмы

**Задача:** одно и то же действие можно выполнить **разными способами**, и способ
хочется выбирать/менять.

**Суть:** каждый алгоритм — отдельный класс за общим интерфейсом; клиент подставляет
нужный.

```java
interface SortStrategy { void sort(int[] data); }
class QuickSort implements SortStrategy { ... }
class BubbleSort implements SortStrategy { ... }

// подставляем нужную стратегию
sorter.setStrategy(new QuickSort());
```

Разница с Factory: Factory решает, **какой объект создать**; Strategy — **как
выполнить действие** (поведение). Часто работают вместе.

## Builder — пошаговое создание сложного объекта

**Задача:** объект с кучей полей (часть обязательна, часть нет) неудобно создавать
конструктором с 10 аргументами.

**Суть:** собираем объект пошагово, читаемо, и в конце вызываем `build()`.

```java
User user = User.builder()
        .name("Аня")
        .email("anya@x.ru")
        .age(25)
        .build();
```

Читается лучше, чем `new User("Аня", "anya@x.ru", 25, null, true)`, и не надо помнить
порядок аргументов. В Java часто генерируется Lombok-аннотацией `@Builder`.

## Что запомнить

- **Singleton** — один экземпляр на приложение (в Spring это бины по умолчанию).
- **Factory** — спрятать создание объекта, вернуть нужную реализацию по параметру.
- **Strategy** — взаимозаменяемые алгоритмы за общим интерфейсом; выбираем поведение.
- **Builder** — пошаговое читаемое создание объекта с многими полями.

# MapStruct

MapStruct — библиотека для **маппинга между объектами**: превращает сущность в DTO
и обратно, генерируя код перекладывания полей на этапе компиляции. Убирает
ручные, скучные и легко устаревающие методы-конвертеры.

## Зачем это

В слоистом приложении наружу отдают DTO, а внутри работают с сущностями (см. слои
приложения). Значит, нужно постоянно перекладывать поля: `User` → `UserDto` и
обратно. Руками это выглядит так:

```java
UserDto dto = new UserDto();
dto.setId(user.getId());
dto.setName(user.getName());
dto.setEmail(user.getEmail());
// ... и так для каждого поля, в каждом маппере
```

Много однообразного кода, который легко забыть обновить при добавлении поля.

## Как выглядит с MapStruct

Описываешь **интерфейс** маппера, а реализацию генерирует MapStruct:

```java
@Mapper(componentModel = "spring")
public interface UserMapper {
    UserDto toDto(User user);
    User toEntity(UserDto dto);
}
```

Поля с совпадающими именами перекладываются автоматически. Где имена/типы не
совпадают — указываешь явно через `@Mapping`.

## Как работает и чем хорош

- **Annotation processor** — генерирует обычный Java-код маппинга при компиляции.
  Это простые вызовы геттеров/сеттеров, **без рефлексии** в рантайме → быстро.
- `componentModel = "spring"` делает маппер **Spring-бином** — его можно
  инжектить как обычную зависимость.
- Сгенерированный код можно посмотреть — никакой рантайм-магии, всё прозрачно.

## MapStruct vs ручной маппинг

- **Ручной** — полный контроль, но много кода и легко забыть поле.
- **MapStruct** — меньше кода, поле-в-поле генерируется автоматически, ошибок
  меньше; за счёт компиляции быстрый. Цена — ещё одна зависимость и генерация в
  сборке.

## Как ответить на интервью

Коротко: MapStruct генерирует маппинг между объектами — сущность в DTO и обратно.
В слоистом приложении постоянно перекладываешь поля между сущностями и DTO, руками
это много однообразного кода. С MapStruct описываешь интерфейс-маппер с методами
`toDto`/`toEntity`, а реализацию генерирует annotation processor при компиляции:
поля с совпадающими именами перекладываются сами, остальное задаёшь через
`@Mapping`. Это обычный код без рефлексии, поэтому быстро, а с
`componentModel = "spring"` маппер становится бином. По сути убирает рутину и
снижает риск забыть поле.

# Рабочие инструменты

Короткий обзор инструментов, которыми backend-разработчик пользуется каждый день
помимо кода. На интервью про них редко спрашивают глубоко, но понимать, что и
зачем, полезно — это часть рабочего процесса.

## IDE

**IntelliJ IDEA** — стандарт для Java. Ценность не в редакторе текста, а в том,
что она понимает код: автодополнение, навигация по классам, рефакторинг,
подсветка ошибок до компиляции, отладчик, интеграция с Git, Maven/Gradle, БД.
Умение пользоваться отладчиком (breakpoints, пошаговое выполнение, просмотр
переменных) экономит куда больше времени, чем логи через `println`.

## Проверка API

- **Postman** / **Insomnia** — GUI для ручной отправки HTTP-запросов к своему API:
  собрать запрос, задать заголовки и тело, посмотреть ответ. Удобно проверять
  эндпоинты и хранить коллекции запросов.
- **curl** — то же из терминала одной командой; удобно для быстрых проверок и
  скриптов.
- **Swagger UI** — если поднят OpenAPI, можно дёргать эндпоинты прямо из
  сгенерированной документации.

## Работа с БД

- **DBeaver** / **DataGrip** — GUI-клиенты к базам: смотреть таблицы, писать и
  отлаживать SQL, изучать структуру. Быстрее, чем всё гонять через приложение.

## Локальное окружение

- **Docker** — поднять локально PostgreSQL, Kafka, Redis одной командой, не
  устанавливая их в систему. `docker compose` — поднять сразу набор сервисов для
  приложения. Для разработчика это способ иметь под рукой нужные зависимости.

## Таск-трекер и документация

- **Jira** / **YouTrack** — задачи, доски, статусы. Работа обычно начинается с
  задачи в трекере и заканчивается связанным с ней PR.
- **Confluence** / вики — командная документация, договорённости, описания
  сервисов.

## Как ответить на интервью

Коротко: основной инструмент — **IntelliJ IDEA**, ценна пониманием кода: навигация,
рефакторинг, и особенно отладчик — им пользуюсь вместо `println`. API проверяю
через **Postman**/**curl** или Swagger UI. К базам хожу GUI-клиентом вроде
**DBeaver**/**DataGrip** — смотреть данные и отлаживать SQL. Локально поднимаю
зависимости (Postgres, Kafka, Redis) через **Docker**/`docker compose`, не
засоряя систему. Задачи веду в трекере (**Jira**/**YouTrack**), документация — в
Confluence/вики; цикл обычно «задача в трекере → ветка → PR».

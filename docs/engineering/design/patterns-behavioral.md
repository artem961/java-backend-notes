# Поведенческие паттерны

Поведенческие паттерны — про то, **как объекты взаимодействуют и распределяют
обязанности**. Разберём те, что реально используются в backend-коде и часто
всплывают на собеседовании.

## Strategy / стратегия

**Проблема:** есть несколько взаимозаменяемых алгоритмов (способы оплаты, расчёта
скидки, доставки), и выбирать нужно в рантайме. Ветвления `if/else` разрастаются.

**Решение:** каждый алгоритм — отдельный класс за общим интерфейсом; нужный
подставляется во время работы.

```java
interface DiscountStrategy { Money apply(Money price); }
class NoDiscount      implements DiscountStrategy { /* ... */ }
class PercentDiscount implements DiscountStrategy { /* ... */ }

class Checkout {
    private final DiscountStrategy discount; // подставили нужную
}
```

- **Плюс:** новый алгоритм = новый класс, старое не трогаем (Open/Closed);
  ветвления исчезают.
- В Spring стратегии удобно инжектить: можно внедрить `List<DiscountStrategy>`
  или `Map<String, DiscountStrategy>` со всеми реализациями сразу.

## Observer / наблюдатель

**Проблема:** при изменении одного объекта нужно уведомить несколько других, но
жёстко связывать их не хочется.

**Решение:** объект-источник хранит список подписчиков и оповещает их о событии;
подписчики реагируют сами.

- Идея лежит в основе **событий**: издатель публикует событие, слушатели на него
  реагируют. В Spring это `ApplicationEventPublisher` и `@EventListener`.
- **Плюс:** источник не знает, кто и как реагирует, — слабая связанность, легко
  добавлять новых слушателей.

## Template Method / шаблонный метод

**Проблема:** несколько процессов имеют одинаковый скелет, но отличаются в
отдельных шагах.

**Решение:** базовый класс задаёт последовательность шагов (шаблон), а конкретные
шаги переопределяют наследники.

- Пример из Spring — многочисленные `...Template` (`JdbcTemplate`,
  `RestTemplate`, `KafkaTemplate`): фреймворк держит общий каркас (соединение,
  обработка ошибок, освобождение ресурсов), а ты задаёшь только суть — запрос
  или обработку строки.

## Command / команда

**Проблема:** нужно представить действие как объект — чтобы складывать в очередь,
логировать, откладывать или отменять.

**Решение:** заворачиваем запрос в объект с методом `execute()`.

- Пример — задачи в пул потоков: `Runnable`/`Callable` — это команды, которые
  кладут в очередь и исполняют отдельные потоки.

## Как ответить на интервью

Коротко: поведенческие паттерны — про взаимодействие объектов. **Стратегия** —
взаимозаменяемые алгоритмы за общим интерфейсом, выбор в рантайме вместо
разрастания `if/else`; в Spring удобно инжектить списком или мапой.
**Наблюдатель** — источник оповещает подписчиков о событии, не зная, кто они;
основа событийной модели, в Spring — `@EventListener`. **Шаблонный метод** —
базовый класс задаёт скелет процесса, наследники переопределяют шаги; так устроены
`JdbcTemplate` и прочие `...Template`. **Команда** — действие как объект с
`execute()`, чтобы ставить в очередь; пример — `Runnable` в пуле потоков.

# Maven

Maven — система сборки и управления зависимостями для Java. Он избавляет от
ручного скачивания библиотек и написания скриптов компиляции: описываешь проект
декларативно, а Maven по стандартной схеме собирает, тестирует и упаковывает.

## Что он делает

- **Управляет зависимостями** — сам скачивает библиотеки и их транзитивные
  зависимости из репозитория (Maven Central) по описанию.
- **Стандартизирует сборку** — у всех Maven-проектов одинаковая структура
  (`src/main/java`, `src/test/java`) и одинаковые команды. Пришёл в чужой проект —
  сразу знаешь, как собрать.
- **Прогоняет жизненный цикл** — компиляция, тесты, упаковка в JAR — по фазам.

## pom.xml

Сердце проекта — файл **`pom.xml`** (Project Object Model). В нём декларативно
описано всё: координаты проекта, зависимости, плагины.

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
        <version>3.3.0</version>
    </dependency>
</dependencies>
```

Каждая зависимость и сам проект адресуются тройкой координат **GAV**:
`groupId` (кто/группа), `artifactId` (что/имя), `version` (версия).

## Жизненный цикл и фазы

Сборка идёт по **фазам**, каждая следующая включает предыдущие:

| Команда | Что делает |
|---|---|
| `mvn compile` | Компилирует исходники |
| `mvn test` | Компилирует и прогоняет тесты |
| `mvn package` | Собирает артефакт (JAR/WAR) |
| `mvn install` | Кладёт артефакт в локальный репозиторий (`~/.m2`) |

Локальный репозиторий `~/.m2` — кэш скачанных зависимостей на машине, чтобы не
качать одно и то же повторно.

## Что полезно знать про зависимости

- **Транзитивность** — подключил библиотеку, её зависимости подтянутся сами.
- **Scope** — область видимости зависимости: `compile` (везде, по умолчанию),
  `test` (только тесты, например JUnit), `provided` (даёт среда, не пакуется).
- Конфликты версий транзитивных зависимостей — отдельная тема (см. зависимости и
  конфликты).

## Как ответить на интервью

Коротко: Maven — система сборки и управления зависимостями. Проект описывается
декларативно в **`pom.xml`**: координаты, зависимости, плагины; каждая
зависимость адресуется тройкой **GAV** (groupId, artifactId, version). Maven сам
качает библиотеки с их транзитивными зависимостями из Maven Central и кэширует в
`~/.m2`. Сборка идёт по фазам жизненного цикла: `compile` → `test` → `package` →
`install`, каждая включает предыдущие. У зависимостей есть scope — `compile`,
`test`, `provided`. Главная ценность — стандартная структура и команды: любой
Maven-проект собирается одинаково.

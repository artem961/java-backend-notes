# PromQL — запросы к метрикам

Сырые метрики сами по себе — просто числа. Чтобы получить из них график «запросов в
секунду» или «доля ошибок», их обрабатывают запросами на языке **PromQL**. Писать
сложные запросы наизусть junior-у не нужно, но понимать пару базовых конструкций —
`rate` и перцентили — стоит: они встречаются в любом дашборде.

## Зачем нужен язык запросов

Prometheus хранит счётчики, которые просто растут, и текущие значения. Чтобы превратить
их в осмысленные графики, нужно посчитать: скорость роста, сумму по инстансам, долю
ошибок, перцентиль. Это и делает PromQL — выбирает нужные ряды по меткам и применяет к
ним функции.

Выбор рядов — по имени и меткам:

```promql
http_server_requests_seconds_count{status="500"}
```

— все ряды этой метрики, где метка `status` равна `500`.

## rate — скорость роста счётчика

Счётчик запросов всё время растёт, и его абсолютное значение неинформативно. Нужна
**скорость** — сколько прибавляется в секунду. Это `rate`:

```promql
rate(http_server_requests_seconds_count[1m])
```

— средний прирост за секунду на интервале в 1 минуту, то есть **RPS**. `rate` — самая
частая функция; на нём строят и нагрузку, и долю ошибок:

```promql
sum(rate(http_server_requests_seconds_count{status=~"5.."}[5m]))
  / sum(rate(http_server_requests_seconds_count[5m]))
```

— доля ошибок 5xx от всех запросов (`=~` — совпадение по регулярке, `5..` — любой 5xx).

## histogram_quantile — перцентили латентности

Латентность собирают гистограммой, а перцентиль (p95/p99) считают функцией
`histogram_quantile`:

```promql
histogram_quantile(0.95,
  sum(rate(http_server_requests_seconds_bucket[5m])) by (le))
```

— p95 времени ответа. `0.95` — какой перцентиль, `le` — метка корзин гистограммы. Это
типовой запрос для панели латентности, его достаточно узнавать и понимать смысл.

## Агрегация по меткам

`sum`, `avg`, `max` схлопывают ряды, а `by` / `without` задают, по каким меткам
группировать:

```promql
sum(rate(http_server_requests_seconds_count[1m])) by (uri)
```

— RPS с разбивкой по эндпоинтам (каждый `uri` — своя линия на графике).

## Как ответить на интервью

Коротко: PromQL — язык запросов к метрикам Prometheus, он превращает сырые ряды в
осмысленные графики. Ряды выбираешь по имени и меткам. Самая частая функция — **`rate`**:
счётчик просто растёт, а `rate` даёт скорость роста в секунду, то есть RPS; на нём же
строят долю ошибок — rate по 5xx поделить на rate по всем. Перцентили латентности считают
**`histogram_quantile`** из гистограммы — например p95 времени ответа. Плюс агрегации
`sum`/`avg` с `by` для группировки, например RPS по эндпоинтам. Наизусть сложные запросы
не пишу, но `rate` и перцентиль в дашборде читаю и понимаю, что они значат.

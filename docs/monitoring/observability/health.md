# Здоровье сервиса

Самый базовый сигнал наблюдаемости — «сервис вообще жив и готов работать?». Для этого у
приложения есть **health check** — специальный эндпоинт, который отвечает коротким
«здоров / болен». Его дёргают не люди, а автоматика: балансировщик, оркестратор,
система мониторинга.

## Зачем нужен health check

Смысл — чтобы **трафик не шёл на больной экземпляр**. Если сервис завис или потерял связь
с базой, он не должен получать запросы: их лучше отдать здоровым копиям. Поэтому:

- **балансировщик** периодически опрашивает health и убирает больной инстанс из ротации;
- **Kubernetes** по пробам решает, перезапустить под или не слать на него трафик
  (см. [Приложение в кластере](../../infrastructure/k8s/app-in-cluster.md));
- **мониторинг** может алертить, если health слишком долго `DOWN`.

## Actuator: health в Spring Boot

В Spring Boot здоровье отдаёт **Spring Boot Actuator** — модуль с готовыми
служебными эндпоинтами. Подключается зависимостью, и появляется
`/actuator/health`:

```json
{
  "status": "UP",
  "components": {
    "db":         { "status": "UP" },
    "diskSpace":  { "status": "UP" },
    "ping":       { "status": "UP" }
  }
}
```

- общий `status` — `UP` (здоров) или `DOWN` (болен);
- **компоненты** — Actuator сам проверяет подключённые ресурсы: базу (сходил ли коннект),
  место на диске, брокер сообщений и т.д. Если хоть один критичный компонент `DOWN` —
  весь сервис `DOWN`.

Actuator умеет и другое (метрики, инфо, дамп конфигурации), но health — самое базовое.

## Liveness и readiness — два разных вопроса

Особенно в Kubernetes health разделяют на две пробы, и это любят спрашивать:

- **liveness** — «сервис **жив** или намертво завис?». Если проба не отвечает — под
  **перезапускают**.
- **readiness** — «сервис **готов принимать трафик**?». Пока не готов (например, ещё
  прогревается или потерял базу) — трафик на него **не шлют**, но не убивают.

Ключевое различие: liveness управляет перезапуском, readiness — маршрутизацией трафика.
Свежезапущенный сервис может быть уже жив (liveness `UP`), но ещё не готов (readiness
`DOWN`), пока не прогрелся.

## Как ответить на интервью

Коротко: health check — это эндпоинт, по которому автоматика понимает, жив ли сервис и
готов ли работать; смысл — не слать трафик на больной экземпляр. В Spring Boot его даёт
**Actuator** через `/actuator/health`: он отдаёт `UP`/`DOWN` и заодно проверяет
подключённые ресурсы — базу, диск, брокер. В Kubernetes здоровье делят на две пробы:
**liveness** — жив или завис, если нет — под перезапускают; **readiness** — готов ли
принимать трафик, если нет — трафик не шлют, но не убивают. Разница в том, чем они
управляют: liveness — перезапуском, readiness — маршрутизацией.

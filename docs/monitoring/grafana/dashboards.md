# Дашборды бэкендера

Prometheus хранит метрики и умеет по ним считать, но смотреть на них удобно не в нём.
Для визуализации используют **Grafana** — она рисует дашборды: наборы графиков, куда
Prometheus отдаёт данные. Важно понимать, **что именно выносит на дашборд бэкендер** —
это технические панели про здоровье сервиса, а не бизнес-графики.

## Grafana и Prometheus — разделение ролей

Их постоянно упоминают вместе, и надо понимать, кто за что:

- **Prometheus** — **собирает и хранит** метрики, считает по ним запросы (PromQL);
- **Grafana** — **показывает**: берёт данные из Prometheus (и других источников) и рисует
  графики, панели, таблицы. Своих метрик не хранит.

То есть Grafana — «монитор», Prometheus — «источник данных» за ним. На каждой панели
Grafana под капотом лежит PromQL-запрос.

## Что выносит на дашборд бэкендер

Дашборд сервиса собирают вокруг здоровья и нагрузки — по сути это визуализированный
**RED плюс ресурсы**:

- **RPS** — нагрузка, запросов в секунду (можно с разбивкой по эндпоинтам);
- **Доля ошибок** — процент 5xx; первое, на что смотрят при инциденте;
- **Латентность p95/p99** — время ответа по перцентилям, а не среднее;
- **JVM** — занятый heap и паузы GC (утечки, всплески латентности от сборки мусора);
- **Пулы** — HikariCP: занятые коннекты и ожидающие запросы (упирается ли в базу);
- **Ресурсы машины/пода** — CPU, память.

Это отличается от бизнес-дашборда (регистрации, конверсия, выручка), который смотрят
продукт и аналитики. Бэкендерский дашборд отвечает на вопрос «**сервис здоров и держит
нагрузку?**», а не «сколько заработали».

## Полезные приёмы

- **Переменные (variables)** — выпадающие списки вверху дашборда (выбрать сервис,
  инстанс, окружение); один дашборд работает для многих сервисов;
- **Единый временной диапазон** — все панели показывают один промежуток, поэтому всплески
  на разных графиках видно рядом и легко сопоставить;
- **Готовые дашборды** — под Spring Boot / Micrometer есть импортируемые шаблоны, не
  обязательно рисовать с нуля.

## Как ответить на интервью

Коротко: Grafana — это визуализация метрик, она рисует дашборды, а данные берёт из
Prometheus; Prometheus хранит и считает, Grafana показывает, под каждой панелью — свой
PromQL-запрос. На дашборд бэкендера выносят технические панели про здоровье сервиса — по
сути RED плюс ресурсы: RPS, доля ошибок 5xx, латентность по перцентилям p95/p99, память и
GC у JVM, состояние пула коннектов к базе, CPU. Это не бизнес-графики вроде конверсии —
те смотрят продукт и аналитики; бэкендерский дашборд отвечает на вопрос, здоров ли сервис
и держит ли нагрузку. Удобно использовать переменные, чтобы один дашборд работал для
разных сервисов, и общий временной диапазон, чтобы сопоставлять всплески на разных
панелях.
